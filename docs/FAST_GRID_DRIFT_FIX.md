# FAST-grid 突发漂移修复（2026-11-10）

## 问题与处理

旧 `fast_grid` 按 FAST 亮度对比响应排序，然后在 5×5 窗口中执行
`cornerSubPix`。FAST 高响应不等于局部二维梯度约束良好；细化可能迁移到另一个
局部结构，并在已经分配完点数配额后合并/剔除特征。FAST 固定对比阈值也会漏掉
GFTT 仍能检测到的低对比角点，导致特征不足。实际回放中视觉更新饥饿触发完整
重初始化，使轨迹跨坐标原点跳变；单纯放宽后端门限不能修复输入质量。

本次仅修改 FAST-grid 路径：

- 在 FAST 候选及其相邻像素上计算稀疏 Shi–Tomasi 最小特征值，要求候选为局部
  极大值，并按该响应排序；使用 1% 相对质量门限。
- 保留符合条件的 FAST 原始像素位置，不再用宽窗口亚像素细化移动它们。
- 保留网格轮转、mask、最小间距和特征数上限。
- FAST 合格候选不能填满当前请求配额时，显式使用完整 GFTT 结果恢复该帧的补点。
  不将两套不同排序混合；通过 DEBUG 日志说明恢复路径。
- 检查有限坐标、图像边界、输入类型和 mask 几何。

`fastCornerMinEigenValue()` 的 3×3 Sobel / 3×3 结构张量评分由 OpenCV
`cornerMinEigenVal(..., 3, 3)` 独立验证。它只计算稀疏位置，无全帧 float 响应缓存。

恢复路径的目的是精度和连续性，**不保证旧 FAST-grid 的性能优势**。低对比/角点
稀疏场景可能频繁回退，额外 FAST 探测和质量检查使其比直接 GFTT 更耗时。
若优先考虑稳定性能，仍可直接使用 `feature_detector: gftt`。

## 复现条件

本地 x86_64，Release，native 优化关闭；当前源码基点 `a0dfc4d`。
使用用户当前 mono YAML 快照：`cam0_pinhole.yaml`、`max_cnt=200`、`min_dist=20`、
`fast_threshold=20`、5×5 网格、双向光流开启、RANSAC 开启、Schur EKF，
EuRoC V2 三序列。算法修复未修改标定、特征数、后端或其门限。

原始证据位于 `output/fast_grid_drift_20261110/`，包括配置全文、源码/二进制
SHA256、原始日志、轨迹、资源与延迟采样。`configs/gftt.yaml` 仅切换检测器，
用于单因素参考。所有报告的正式回放为完整序列 1×；加速回放仅用于候选筛选。

## 验证

| V2_02_medium | 0.3469 | 0.3597 | 0.2735 | 0→0 | 0.10→0.10 |

共同时间戳 ATE：easy `1.0145→0.1788 m`，medium `0.3469→0.3597 m`，
difficult `1.9488→0.4037 m`。修复消除了本轮 easy/difficult 的重初始化跳变，
但 medium 误差略增约 1.3 cm，不声称所有场景精度全面提升。

相邻输出的最大位置变化：easy `8.085→0.107 m`；difficult `6.060→0.292 m`。
这些是轨迹输出步长，包含正常运动及重初始化，不是拟合后的瞬时定位误差。

CPU 时间（旧 FAST / 修复 / GFTT，秒）：easy `10.62/19.74/14.86`，medium
`10.81/23.64/15.59`，difficult `7.39/20.14/14.28`。旧版因重初始化少输出，
其 CPU 与修复版不能简单视为同量工作对比。修复版在本机的开销高于直接 GFTT，
不作为加速结论；优先稳定且对性能敏感时可直接选择 GFTT。

- 12 个 CTest 程序、140 个 C++ 用例通过，前端 25 项通过。
- 两个新增行为测试与旧库链接时均失败、与修复库链接时均通过：低对比角点恢复、
  完整 FAST 点集的二维响应局部极大值约束。
- clang-format 改动区域及 clang-tidy 检查通过。
- 重启计数区分 request 与 reset entry，不把日志中的请求当作完成重启。
- ARM 旧实验工作区与当前接口版本不同；本轮未覆盖旧源码、未在 ARM 编译/回放。
  这里的性能与精度数据均来自本地 x86_64。

重复验证：easy/difficult 各另做一次完整 1× 回放，ATE 分别仍为 `0.180205 m` /
`0.411984 m`，两次轨迹全部 8 列逐位一致，均无重启。54 项 Python 测试通过。
最终数字见 `FAST_GRID_DRIFT_RESULTS.json`。有限序列的重复不等于所有输入都不会漂移。

原始候选筛选中，仅做评分、细化后拒绝大位移、以及仅做数量不足恢复均未稳定
困难序列，已弃用；最终保留局部响应极大值约束及 GFTT 恢复，未保留未经验证的
3px 位移硬门限。
